Appendix C: Viva Questions & Answers

Q1. Why did you use Jira?
Jira is the software platform used to operationalize Agile work management. It makes work visible, traceable, and decomposable. It is not an Agile methodology itself, but an execution tool.
Q2. What is an Epic?
An Epic is a large product capability that groups related User Stories. For example, "KAN-1 Authentication & User Management" represents a major product area.
Q3. What is a User Story?
A feature expressed from the user's perspective focusing on business value (As a... I want to... So that...).
Q4. Why are acceptance criteria important?
They define the observable conditions that determine whether a Story is actually complete and testable, forming the basis of the Definition of Done.
Q5. What is a Subtask?
A breakdown of a User Story into concrete technical implementation activities (e.g., KAN-11 Registration is broken into UI design, DB tables, and tests).
Q6. What is the difference between Epic and Story?
An Epic is a high-level grouping of requirements. A Story is a specific, deliverable increment of value within that Epic.
Q7. What is a Bug in Agile?
A visible defect or quality deviation kept in the backlog, triaged, and fixed rather than hidden outside the project management system.
Q8. What is Story Point estimation?
A relative measure of effort, complexity, and risk used for planning iteration capacity.
Q9. Why are Story Points not hours?
Hours vary by developer experience; points represent absolute complexity which remains constant regardless of who does the work.
Q10. What is Scrum?
An Agile framework providing governance, iteration structure, ceremonies (Daily Scrum, Planning), and backlog artifacts.
Q11. What is Kanban?
An Agile framework focused on continuous visual flow, limiting WIP, and pulling work through a board without necessarily using time-boxed iterations.
Q12. What is XP?
Extreme Programming, focused on engineering quality practices like automated testing, continuous integration, and small code increments.
Q13. What is Lean?
A philosophy focused on reducing waste, managing dependencies, preventing bottlenecks, and optimizing the flow of value delivery.
Q14. How does Jira support Agile?
It provides the executable layer (boards, backlogs, issue hierarchies, workflows) to track and manage Agile artifacts.
Q15. How does the Alumnex board represent Kanban?
Through a continuous, visible flow from Idea → To Do → In Progress → In Review → Done, where bottlenecks can be visually identified.
Q16. Where is Scrum applied?
It is documented as the intended governance and iteration model via stories KAN-55 through KAN-63, guiding backlog refinement and quality gates.
Q17. Where is XP applied?
In the engineering backlog items like KAN-52 (Automated Testing) and KAN-53 (CI/CD Pipeline).
Q18. Where is Lean applied?
Through explicit dependency tracking (Blocks), visual workflows to reduce wait times, and continuous improvement metrics.
Q19. What is Definition of Done?
The quality gate determining when work can leave execution (code written, tested, documented, and reviewed).
Q20. What is Definition of Ready?
The quality gate determining if a story is refined, understood, and testable enough to safely enter execution.
Q21. What are dependencies?
Sequencing constraints where one story blocks another (e.g., Mobile Auth blocks Mobile Notifications). Tracked via "Blocks" issue links.
Q22. Why are Jira Versions used?
To group completed work into deliverable release phases (Phase 1-5), providing a high-level roadmap.
Q23. What is the role of Confluence?
It serves as the documentation and knowledge layer (playbooks, meeting notes, project plans).
Q24. What is the difference between Jira & Confluence?
Jira tracks execution ("what work is being done"); Confluence tracks knowledge and governance ("how and why it is managed").
Q25. Does the current board have actual Scrum Sprints?
No. The KAN project is a simple team-managed board without native sprint history. Scrum is our documented operating model for governance.
Q26. Why does the project not show native Story Points?
The team-managed configuration limits custom fields, so estimates (totaling 256) are securely documented in the story descriptions and baseline document.
Q27. What do the current status counts represent?
They represent a current project-management snapshot of active visualization, not a historical sprint completion record.
